## Security & unlock
| # | Topic | Decision | Why |
|---|---|---|---|
| S1 | Threat model | Promise only what we protect (see SECURITY_DESIGN.md). Rooted/compromised devices and malware active while vault is open are **out of scope** | Honest scoping |
| S2 | Unlock | **App PIN (required, 6 digits)** OR **biometric (optional)** — either one unlocks | Familiar banking-app model; simpler than 2-factor-every-time |
| S3 | Wrong PIN | After **3 wrong PIN attempts → locked; only recovery words unlock.** No timed waits. Biometric is **also blocked** once PIN attempts are exhausted | Max security |
| S4 | Attempt counter | ~~Increment and persist **before** verifying the PIN (prevents kill-app bypass). Successful unlock resets to 0 (assumed — confirm)~~ ~~superseded by S12~~ | |
| S5 | Recovery words | 12-word BIP-39-style phrase (128-bit). Generated **once per installation**, device-bound, **never regenerated** (not even after PIN reset). Shown once; FLAG_SECURE; no copy; type-back confirmation; never stored on device | Recover forgotten PIN; device-bound so leaked words alone are useless. **12 confirmed** (not 24): K_device binding already covers the extra margin; 24 doubles transcription burden → more real lockouts |
| S6 | No recovery possible | Vault stays **locked** (not wiped) | |
| S7 | Session | ~~Vault auto-locks after **5 minutes**, and immediately on screen-off~~ ~~refined by S23~~ | |
| S8 | Display | Usernames shown; **passwords masked**, revealed only via eye icon; auto re-mask after a few seconds and on backgrounding | |
| S9 | In-memory protection | KeePass-style second layer: secrets stay encrypted in memory with an ephemeral session key; decrypted only on reveal/copy/autofill; key discarded on lock | |
| S10 | Reveal auto-mask timeout | **20 s**, timer **restarts on each eye-icon tap**; still re-masks immediately on backgrounding / screen-off (S8) | Long enough to type onto a TV/other device; re-tap extends without adding a setting |
| S11 | Clipboard clear | Clear after **30 s** or **immediately on vault lock** (5-min session / screen-off), whichever first; clip marked sensitive | Covers a normal switch-and-paste; lock means no secret outlives the session. Impl note: background apps can't read the clipboard (Android 10+), so verify how to avoid wiping user's newer clip |
| S12 | Attempt counter | Increment and persist **before** verifying the PIN. **Any successful unlock (PIN or biometric) resets to 0**; successful recovery also resets. After unlock, if failures > 0 show **"N wrong PIN attempts since your last unlock"** | Typos never accumulate; repeat-access attacker gains only ~2/1M per cycle (negligible); notice tips off the owner. At 3, biometric is blocked (S3) so only recovery resets |
| S13 | Autofill: app identity | Match apps by **package name + signing-cert SHA-256**, pinned when the entry is linked. Cert change → user re-links | Package name alone is spoofable by sideloaded apps (Aonzo et al. 2018 autofill phishing) |
| S14 | Autofill: web matching | Match on **registrable domain (eTLD+1)** using a **bundled Public Suffix List** (refreshed with app releases). Trust `webDomain` **only from an allowlist of known browsers** (package + cert); otherwise treat requester as an app (S13) | Matches user expectation across subdomains; PSL blocks `a.github.io`↔`b.github.io`; stops fake "browsers" claiming a bank domain |
| S15 | Autofill: app↔website linking | **Manual only**: in an unmatched app, user searches vault and taps "Remember for this app" → stores package + cert on that entry. No Digital Asset Links, no bundled mapping list | Offline, explicit, unspoofable; one-time tap per app |
| S16 | Autofill: ground rules | **Never fill without user tap** (always a suggestion to pick). Locked → single "Unlock OffGrid Vault" suggestion via PIN/biometric, respecting lockout (S3). Never offer non-matching entries; only "Search vault…" when no match | No silent fills, no leaking entry names to the wrong app |
| S17 | Attempt counter storage | Own small file in app-private storage, written **synchronously** (`AtomicFile` + fsync, or `SharedPreferences.commit()` — **never `apply()`**) **before** PIN verification. No Keystore "protection" claimed; enforcement relies on the app sandbox | A Keystore MAC can't stop replay of an old valid value; anyone who can replace app files is rooted (out of scope). `apply()` is async → kill-app bypass of S12 *(Claude rec., approved by Kalyan 2026-10-02)* |
| S18 | Clipboard clearing mechanics | In-process timer clears at 30 s / on lock via `clearPrimaryClip()` without reading first (background apps can't read the clipboard, Android 10+). Persist a "pending clear" flag; if the process died, clear on next app start. Accept edge case: a newer clip copied by the user within 30 s may also be cleared. Verify on real devices (Android 11 + 13+) | Can't inspect clipboard in background, so clear unconditionally; persisted flag covers process death *(Claude rec., approved by Kalyan 2026-10-02)* |
| S19 | PIN quality | Reject common PINs at setup/change: bundled blocklist of most-common 6-digit PINs + patterns (all same digit, ascending/descending runs, repeated pairs/triples like `121212`, `123123`) | With only 3 attempts, attackers try the top-3 PINs first; blocking them removes most of the realistic risk *(Claude rec., approved by Kalyan 2026-10-02)* |
| S20 | Input hygiene | PIN entered via **in-app number pad** (no system keyboard). All secret fields: `textPassword`/`textNoSuggestions` + `IME_FLAG_NO_PERSONALIZED_LEARNING`. App's own screens set `importantForAutofill="noExcludeDescendants"` so other autofill services can't capture/save vault contents | Keyboards and third-party autofill services are the easiest leak path for typed secrets *(Claude rec., approved by Kalyan 2026-10-02)* |
| S21 | Lock-screen-gated keys | `K_device` and `K_bio` created with `setUnlockedDeviceRequired(true)` (unusable while phone is locked). **Conditional:** ship only after on-device tests prove `K_device` survives changing **and removing** the phone screen lock and StrongBox/TEE fallback works — if `K_device` is lost, the vault (and recovery words) are useless | Blocks attacks on a seized, locked phone; but losing K_device = permanent data loss, so must be verified first *(Claude rec., approved by Kalyan 2026-10-02)* |
| S22 | Device screen lock required | Setup requires a secure lock screen (`KeyguardManager.isDeviceSecure()`); if removed later, app explains and blocks unlock until one is set again (vault not deleted) | Without it, Android's file-based encryption isn't credential-bound and biometric is unavailable *(Claude rec., approved by Kalyan 2026-10-02)* |
| S23 | Session timing | Auto-lock after **5 minutes of inactivity** (timer reset by user interaction); **immediate lock on screen-off**; switching to another app does **not** lock (copy-paste/autofill workflows) | Refines S7's ambiguity *(Claude rec., approved by Kalyan 2026-10-02)* |
| S24 | PIN change | Requires the **current PIN** (biometric not sufficient); wrong attempts count toward the S3 limit. Forgotten PIN → recovery flow only | Prevents someone with a borrowed unlocked session or fingerprint from taking over the vault *(Claude rec., approved by Kalyan 2026-10-02)* |
| S25 | Extra hardening | `setAccessibilityDataSensitive(true)` on secret views (API 34+). **No root detection** (out of scope, trivially bypassed). Docs state memory wiping is best-effort on the JVM | Cheap protection; honest scope *(Claude rec., approved by Kalyan 2026-10-02)* |

## Tech stack
| # | Topic | Decision | Why |
|---|---|---|---|
| T1 | UI toolkit | **Jetpack Compose**; wrapped `EditText` (`AndroidView`) for secret inputs **only if** a spike shows Compose can't set `IME_FLAG_NO_PERSONALIZED_LEARNING` on non-password fields | Modern standard; Views only where security needs exact control *(Claude rec., approved by Kalyan 2026-10-02)* |
| T2 | Compose window security | Every `Dialog` / `Popup` / bottom sheet uses `SecureFlagPolicy.SecureOn` (separate windows don't reliably inherit FLAG_SECURE) | Prevents a dialog showing secrets being screenshot/cast *(Claude rec., approved by Kalyan 2026-10-02)* |
| T3 | Architecture | **Single Activity**, MVVM with unidirectional state (`ViewModel` + `StateFlow`), Compose Navigation. One process-wide `VaultSession` (lock state, DEK, session key) shared by UI and Autofill service; lock = one call that wipes and emits `Locked` | One source of truth for lock state; autofill and UI can't disagree *(Claude rec., approved by Kalyan 2026-10-02)* |
| T4 | Modules | `:app` (UI, nav), `:core:crypto` (Argon2, AEAD, HKDF, BIP-39, Keystore), `:core:vault` (format, Protobuf, storage, session), `:autofill` (service, matching, PSL) | Crypto/format testable in isolation; clear review boundaries *(Claude rec., approved by Kalyan 2026-10-02)* |
| T5 | Dependency injection | **Manual DI** (single `AppContainer`), no Hilt/Koin | Small app; fewer dependencies and no annotation processing = smaller supply-chain and review surface *(Claude rec., approved by Kalyan 2026-10-02)* |
| T6 | Async | Kotlin Coroutines; Argon2/IO on `Dispatchers.Default`/`IO` | Standard; keeps 0.5–1 s KDF off the main thread *(Claude rec., approved by Kalyan 2026-10-02)* |
| T7 | Protobuf | **Wire** (Square), Kotlin codegen. Secret fields typed `bytes` and marked `[(wire.redacted) = true]` | Kotlin-first, small runtime; `redacted` keeps secrets out of `toString()`/logs *(Claude rec., approved by Kalyan 2026-10-02)* |
| T8 | Software AEAD + HKDF | **Google Tink** (`tink-android`) for AES-256-GCM on DEK/KEK operations (NO_PREFIX; Tink generates nonces) and HKDF-SHA256. **JCA `AndroidKeyStore`** only for Keystore keys (K_device, K_bio), where Keystore generates the IV | Vetted, misuse-resistant (no hand-managed nonces); Android lacks public HKDF *(Claude rec., approved by Kalyan 2026-10-02)* |
| T9 | Public Suffix List | Bundle official `public_suffix_list.dat` as an asset (refreshed manually per release, committed); small own matcher tested against the official PSL test file. No OkHttp/Guava | No network library in a no-network app; data, not crypto *(Claude rec., approved by Kalyan 2026-10-02)* |
| T10 | BIP-39 | Bundle official English wordlist; small own encode/decode + checksum (SHA-256 via JCA), tested against official BIP-39 test vectors. Entropy → HKDF (no BIP-39 PBKDF2 seed) | Encoding, not a crypto primitive; avoids pulling a crypto-wallet library *(Claude rec., approved by Kalyan 2026-10-02)* |
| T11 | Other AndroidX | `androidx.biometric`, `androidx.autofill` (inline suggestions), `androidx.core` `AtomicFile`. No DataStore (own counter file per S17) | Minimal, first-party *(Claude rec., approved by Kalyan 2026-10-02)* |
| T12 | Build | Gradle Kotlin DSL + version catalog; JDK 17; latest stable AGP/Kotlin/Compose BOM; `targetSdk` = Play's current requirement; R8 full mode in release; release strips `android.util.Log` via `-assumenosideeffects` | Standard, reproducible, smaller attack surface *(Claude rec., approved by Kalyan 2026-10-02)* |
| T13 | Supply chain | **Gradle dependency verification** (`verification-metadata.xml`, SHA-256) + dependency locking. Manifest has `<uses-permission android:name="android.permission.INTERNET" tools:node="remove"/>` **and** a Gradle check task that fails the build if the merged manifest contains INTERNET | Enforces the hard constraint mechanically, not by memory *(Claude rec., approved by Kalyan 2026-10-02)* |
| T14 | Quality gates | Android Lint (security checks as errors) + **detekt** with `ForbiddenImport`/`ForbiddenMethodCall` banning `android.util.Log`/`println`; JUnit4 + kotlin.test unit tests; instrumented tests on emulator + one real cheap phone for Keystore/biometric/Argon2. **GitHub Actions** CI: build, unit tests, lint, detekt, manifest check | Automated guardrails on every push *(Claude rec., approved by Kalyan 2026-10-02)* |
| T15 | Visual style | **NeoPOP-inspired** (CRED's open-sourced design system), **two-tone**: dark hero/header bands (`#0D0D0D`) over light bodies (`#F1F1EE`/white), sharp corners, 3D "pop" buttons with bevelled right/bottom edges, **lowercase serif headlines ending in a full stop** + **wide-tracked uppercase labels**, one accent (mint `#4DFFB4` on dark, deep green `#0E7A50` for text on light), coral/amber for danger/warning. Inspired, not copied: no CRED fonts (Cirka/Gilroy are commercial → Fraunces + Manrope + JetBrains Mono), logos or screens | Kalyan likes the NeoPOP look; two-tone keeps contrast high and secret areas visually distinct |
| T16 | NeoPOP components | **Own Compose components** (pop button, sharp card, label, headline; edges via `drawBehind`, press = offset animation). **Fallback:** `neopop-android` (Apache-2.0, GPL-3.0-compatible) if tilt/shimmer effects prove too costly — then wrap via `AndroidView`, vet per T13, keep its NOTICE | Static edges + press are small to build; library is View-based (verify), so wrapping every component in Compose costs more than writing them *(Claude rec.; Kalyan OK'd library as fallback, 2026-10-02)* |

## Crypto & storage
| # | Topic | Decision | Why |
|---|---|---|---|
| C1 | KDF | **Argon2id** (params TBD by benchmark; industry norm 32–64 MiB) | Modern standard (RFC 9106), GPU + side-channel resistant |
| C2 | Cipher | **AES-256-GCM** (AEAD) | Hardware-accelerated on Android 11+, native to Android Keystore, one cipher everywhere |
| C3 | Key hierarchy | Envelope encryption: random **vault key (DEK)** wrapped separately per unlock method (PIN, biometric, recovery) | Multiple unlock paths without storing secrets in plaintext |
| C4 | Vault structure | **Single encrypted file** (whole vault) | Simplest; hides metadata; atomic; fine at personal scale |
| C5 | Saving | Temp file + fsync + atomic rename (`AtomicFile`), **plus keep `vault.prev`** as crash-safety fallback | Never corrupt the only copy |
| C6 | Header | Versioned header, **authenticated as AEAD associated data** | Tamper-evident, future upgrades |
| C7 | Rollback protection | ~~**Included**: monotonic version counter protected by Keystore; reject older files. Exception: allow `vault.prev` (exactly one version back) **only if current file fails to decrypt**~~ ~~superseded by C17~~ | |
| C8 | Serialization | **Protobuf** | Compact, schema evolution |
| C9 | Password history | Each entry keeps previous passwords with timestamps, shown in-app, masked + in-memory protected like current passwords | Kalyan wants previous values visible |
| C10 | File format | **Custom format** (not KDBX 4, not SQLCipher) | KDBX implies export/interop; SQLCipher adds failure modes |
| C11 | Min Android | ~~**Proposed: Android 11 (API 30)** — not yet confirmed~~ ~~superseded by C12~~ | Keystore auth semantics needed by unlock design |
| C12 | Min Android | **minSdk 30 (Android 11)** — confirmed | Single auth code path (`setUserAuthenticationParameters(0, AUTH_BIOMETRIC_STRONG)`, no API 23–29 fallback) + inline autofill suggestions on every supported device. Device-credential reason dropped (app uses its own PIN) |
| C13 | Argon2id library | **Lazysodium-android** (libsodium `crypto_pwhash`, Argon2id v1.3), used **only for Argon2id**; AES-GCM stays on Keystore/JCA. Fallback: argon2kt | Most-audited core; native speed = stronger params in same unlock time; 5.2.0 (May 2025) bundles libsodium 1.0.20 with 16 KB-aligned `.so` (Play requirement). Slow release cadence acceptable since only Argon2 is used. Must pass RFC 9106 test vectors; verify JNA `.so` is 16 KB-aligned and merged manifest has no INTERNET |
| C14 | Argon2id parameters | **m = 64 MiB fixed, p = 1 (libsodium), t calibrated on-device at setup** to ~0.5–1 s, **floor t = 2** (libsodium INTERACTIVE). Params + salt stored in header; recalibrated on PIN change | Vault is device-bound, so calibrating on the actual phone is safe; floor guarantees never weaker than the standard preset. Argon2's job is slowing on-device brute force if K_device is reachable (e.g. root): ~1M PINs × ~0.7 s ≈ 8 days |
| C15 | Password history depth | **Max 5 previous passwords per entry** (oldest dropped when a 6th is added) + per-entry **"Clear history"** action | Real value is in the last 1–3; fewer old secrets kept = less exposure. Clear history lets users deliberately shrink exposure |
| C16 | Header changes | **Any header change is a normal full save**: PIN change, biometric add/remove, recovery reset, Argon2 recalibration → fresh nonce, re-encrypt payload under the same DEK. Header stays fully AAD | Header (salt, params, wrapped keys) is AAD, so it can't change without re-encrypting; payload is small so cost is negligible; keeps wrapped-key blobs tamper-evident *(Claude rec., approved by Kalyan 2026-10-02)* |
| C17 | Rollback protection (revised) | **No separate Keystore-protected rollback counter.** Header carries a monotonic `generation` (AAD-authenticated) used only to order `vault.bin` vs `vault.prev`. Threat model states file rollback is out of scope (needs root / FBE bypass) | Keystore can't hold a monotonic counter; any counter stored in the app sandbox can be rolled back together with the vault by the same attacker. On a non-rooted device the sandbox + file-based encryption already block file swaps. Removes complexity that gave no real protection *(Claude rec., approved by Kalyan 2026-10-02)* |
| C18 | `vault.prev` fallback + secure deletion | Open `vault.bin`; **only if it fails to decrypt/parse**, try `vault.prev`; on success show "Restored from previous save — your last change may be missing" and re-save immediately. **Security-sensitive saves are written twice** (so `vault.prev` holds no stale secret): PIN change, recovery reset, biometric removal, entry delete, clear history. Residual: flash wear-levelling may keep old encrypted blocks — documented, out of scope | `vault.prev` protects against bugs/corruption, not attackers (C17). Double-save fixes "Clear history"/deleted entry/old-PIN-wrapped key lingering in `vault.prev` *(Claude rec., approved by Kalyan 2026-10-02)* |
